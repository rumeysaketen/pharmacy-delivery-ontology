🏥 Overview

The Pharmacy Delivery Ontology (PDO) formally represents the domain of online pharmacy delivery. It captures the entities, relationships, and constraints of a system where customers order medications—including prescription drugs—and receive them at home via courier.

The ontology was designed using Protégé 5.6, serialized in OWL/XML, and the accompanying knowledge graph is encoded in RDF/Turtle. Data quality is enforced using SHACL shapes, and the graph is queryable via SPARQL 1.1.

📦 Classes

The ontology defines 6 core classes. All are subclasses of owl:Thing.

👤

User

A customer who places medication orders through the delivery platform.

pdo:User
💊

Medicine

A pharmaceutical product dispensed to customers. May be prescription-only or OTC.

pdo:Medicine
📋

Order

A purchase request placed by a user, containing one or more medicines.

pdo:Order
🏪

Pharmacy

A licensed establishment that stocks and dispatches medicines for delivery.

pdo:Pharmacy
📄

Prescription

A doctor-issued authorization that allows dispensing of prescription medicines.

pdo:Prescription
🚴

DeliveryPerson

A courier responsible for picking up and delivering orders to customers.

pdo:DeliveryPerson

🔍 SPARQL Queries

Query 1 – Users and their Orders

Lists all users with the orders they have placed, including status and total price.

SELECT ?userName ?orderID ?orderStatus ?totalPrice
WHERE {
    ?user  rdf:type        pdo:User .
    ?user  pdo:placesOrder ?order .
    ?order pdo:orderID     ?orderID .
    ?order pdo:orderStatus ?orderStatus .
    ?order pdo:totalPrice  ?totalPrice .
    BIND(REPLACE(STR(?user), ".*#", "") AS ?userName)
}
ORDER BY ?userName

Query 2 – Prescription Medicines

Retrieves all medicines linked to a prescription, with prescription metadata.

SELECT ?medicineName ?brandName ?prescriptionID ?issueDate ?doctor
WHERE {
    ?medicine     rdf:type                  pdo:Medicine .
    ?medicine     pdo:requiresPrescription  ?prescription .
    ?medicine     pdo:medicineName          ?medicineName .
    ?prescription pdo:prescriptionID        ?prescriptionID .
    OPTIONAL { ?medicine     pdo:brandName      ?brandName  . }
    OPTIONAL { ?prescription pdo:issueDate      ?issueDate  . }
    OPTIONAL { ?prescription pdo:issuedByDoctor ?doctor    . }
}

Query 3 – Orders by Courier

Groups all delivered orders by courier, showing vehicle type and delivery fees.

SELECT ?courierID ?vehicleType ?orderID ?orderStatus ?deliveryFee
WHERE {
    ?order   rdf:type         pdo:Order .
    ?order   pdo:deliveredBy  ?courier .
    ?order   pdo:orderID      ?orderID .
    ?order   pdo:orderStatus  ?orderStatus .
    ?order   pdo:deliveryFee  ?deliveryFee .
    OPTIONAL { ?courier pdo:courierID   ?courierID  . }
    OPTIONAL { ?courier pdo:vehicleType ?vehicleType . }
}
ORDER BY ?courierID

Query 4 – Pharmacy Medicine Stock

Lists all medicines stocked by each pharmacy with price and stock quantity.

SELECT ?pharmacyName ?city ?medicineName ?price ?stockQuantity
WHERE {
    ?medicine rdf:type       pdo:Medicine .
    ?medicine pdo:providedBy ?pharmacy .
    ?medicine pdo:medicineName ?medicineName .
    ?pharmacy pdo:pharmacyName ?pharmacyName .
    OPTIONAL { ?pharmacy pdo:city          ?city         . }
    OPTIONAL { ?medicine pdo:price         ?price        . }
    OPTIONAL { ?medicine pdo:stockQuantity ?stockQuantity . }
}
ORDER BY ?pharmacyName ?medicineName

Query 5 – Full Order Pipeline (Complex)

Traverses the complete chain: User → Order → Medicine → Prescription → Pharmacy → Courier.

SELECT ?userFirstName ?orderID ?medicineName ?prescriptionID
       ?pharmacyName ?courierFirstName ?vehicleType ?totalPrice
WHERE {
    ?user     pdo:placesOrder     ?order .
    ?order    pdo:containMedicine ?medicine .
    ?medicine pdo:medicineName    ?medicineName .
    ?order    pdo:orderID         ?orderID .
    OPTIONAL { ?user pdo:firstName ?userFirstName . }
    OPTIONAL { ?order pdo:totalPrice ?totalPrice . }
    OPTIONAL {
        ?medicine pdo:requiresPrescription ?presc .
        ?presc pdo:prescriptionID ?prescriptionID .
    }
    OPTIONAL {
        ?order pdo:dispatchedFromPharmacy ?ph .
        ?ph pdo:pharmacyName ?pharmacyName .
    }
    OPTIONAL {
        ?order pdo:deliveredBy ?c .
        ?c pdo:firstName  ?courierFirstName .
        ?c pdo:vehicleType ?vehicleType .
    }
}
ORDER BY ?orderID

✅ SHACL Validation

Six NodeShapes enforce data quality constraints across all classes.

👤 pdo:UserShape → targets pdo:User

pdo:firstNameminCount 1, maxCount 1, xsd:string
pdo:lastNameminCount 1, maxCount 1, xsd:string
pdo:emailminCount 1, valid email pattern regex
pdo:placesOrderrange must be pdo:Order

📋 pdo:OrderShape → targets pdo:Order

pdo:orderIDminCount 1, maxCount 1, xsd:string
pdo:orderStatusenum: pending | processing | shipped | in-transit | delivered | cancelled
pdo:totalPricexsd:decimal, minExclusive 0
pdo:containMedicineminCount 1, range pdo:Medicine
pdo:deliveryFeexsd:decimal, minInclusive 0

💊 pdo:MedicineShape → targets pdo:Medicine

pdo:medicineNameminCount 1, maxCount 1, xsd:string
pdo:providedByminCount 1, range pdo:Pharmacy
pdo:pricexsd:decimal, minExclusive 0
pdo:stockQuantityxsd:integer, minInclusive 0
pdo:dosageFormenum: tablet | capsule | syrup | solution | injection | cream | patch | inhaler

📄 pdo:PrescriptionShape → targets pdo:Prescription

pdo:prescriptionIDminCount 1, pattern: RX-YYYY-NNN
pdo:issueDateminCount 1, xsd:date
pdo:issuedByDoctorminCount 1, xsd:string

🏪 pdo:PharmacyShape → targets pdo:Pharmacy

pdo:pharmacyNameminCount 1, maxCount 1, xsd:string
pdo:pharmacyIDminCount 1, maxCount 1, xsd:string

🚴 pdo:DeliveryPersonShape → targets pdo:DeliveryPerson
