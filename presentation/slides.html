Problem Definition & Motivation

Why Pharmacy Delivery?

🏥 Domain Context

  • Online pharmacy delivery grew 300% post-COVID
  • Multiple stakeholders with complex relationships
  • Prescription validation is legally required
  • Data interoperability across systems is critical

❓ Research Questions

  • How to formally model a delivery workflow?
  • Which medicines require valid prescriptions?
  • How to enforce data quality constraints?
  • Can an LLM query the KG in natural language?

🎯 Solution Approach

Build a formal OWL ontology + RDF/Turtle Knowledge Graph with SPARQL queries, SHACL validation, and LLM integration for natural-language querying.

Project Objectives

What We Built

  • 1. OWL Ontology — 6 classes, 5 object properties, 20+ data properties in Protégé
  • 2. Knowledge Graph — 31 named individuals in RDF/Turtle (pharmacy-kg.ttl)
  • 3. SPARQL Queries — 5 queries from simple lookups to complex multi-hop pipeline
  • 4. SHACL Validation — 6 NodeShapes enforcing data integrity, all constraints passing
  • 5. LLM Integration — KG-grounded Q&A system with hallucination mitigation
  • 6. Documentation — WIDOCO-style HTML docs + GitHub repository

Knowledge Graph Construction

Building the Knowledge Graph

Data Acquisition

  • Synthetic but realistic Turkish pharmacy scenario
  • 3 cities: Istanbul, Ankara, Izmir
  • Real medicine names, INN names, dosage forms
  • Prescription IDs follow RX-YYYY-NNN pattern

Encoding

  • RDF/Turtle format (pharmacy-kg.ttl)
  • Loaded + merged with OWL via rdflib
  • Programmatic extension demo with pdo:Ali

SPARQL Queries & Competency Questions

5 Queries — Simple to Complex

Query Overview

Q1Users & their placed orders
Q2Prescription medicines + metadata
Q3Orders grouped by courier
Q4Pharmacy stock with prices
Q5Full pipeline: 6-class join ⭐

Q5 Result (sample): Ayse | ORD-2026-001 | Paracetamol | RX-2026-001 | Güven Eczanesi | Kemal | 12.50 TL

Query 5 — Complex Pipeline

SELECT ?firstName ?orderID
       ?medicineName ?prescriptionID
       ?pharmacyName ?courierName
WHERE {
  ?user pdo:placesOrder ?order .
  ?order pdo:containMedicine ?med .
  ?order pdo:orderID ?orderID .
  ?med pdo:medicineName ?medicineName .
  OPTIONAL { ?med pdo:requiresPrescription
    ?presc . ?presc pdo:prescriptionID
    ?prescriptionID . }
  OPTIONAL { ?order
    pdo:dispatchedFromPharmacy ?ph .
    ?ph pdo:pharmacyName ?pharmacyName .}
  OPTIONAL { ?order pdo:deliveredBy
    ?c . ?c pdo:firstName ?courierName .}
}

SHACL Validation — All Constraints Passing ✅

PrescriptionShapeID pattern RX-YYYY-NNN, issueDate, doctor

Constraint Example

# Prescription ID pattern
pdo:PrescriptionShape
  a sh:NodeShape ;
  sh:targetClass pdo:Prescription ;
  sh:property [
    sh:path pdo:prescriptionID ;
    sh:minCount 1 ;
    sh:pattern
      "^RX-\\d{4}-\\d{3,}$" ;
    sh:message
      "Must match RX-YYYY-NNN" ;
  ] .

LLM Integration

KG-Grounded Natural Language Q&A

Architecture (RAG pattern)

1. KG Load

rdflib loads pharmacy-kg.ttl + pharmacy.owl (312 triples)

↓
2. SPARQL Context Extraction

3 queries extract orders, prescriptions, couriers as plain text

↓
3. Grounded Prompt → GPT-4o-mini

Context + question → temperature 0.0 → factual answer

Demo Q&A (from KG facts)

Q: Which medicines require a prescription?

A: Based on the KG: Paracetamol → RX-2026-001 (Dr. Mehmet Yilmaz), Amoxicillin → RX-2026-002 (Dr. Fatma Sahin)… Ibuprofen and VitaminD are OTC.

Q: Which courier delivered the most orders?

A: Kemal Arslan (motorcycle, rating 4.8) handled 3 orders: ORD-001, ORD-003, ORD-005 — all delivered.

🛡️ Hallucination mitigation: temperature=0.0 + KG-only context + "not in KG" fallback

Evaluation & Discussion

Findings, Limitations & Future Work

✅ Strengths

  • Complete workflow from order to delivery
  • Prescription as a first-class ontology concept
  • Strict SHACL constraints (0 violations)
  • Fully reproducible via Python script
  • LLM grounded in KG — no hallucination

⚠️ Limitations

  • Synthetic data (not from real pharmacy DB)
  • No OWL reasoning rules (SWRL)
  • No temporal constraint enforcement
  • WIDOCO HTML manual (Java tool not available)

🚀 Future Work

  • Add Doctor & InsuranceCompany classes
  • SWRL rules for order status inference
  • Integrate TITCK (Turkey drug DB) via SPARQL federation
  • Deploy on Apache Jena Fuseki as live endpoint
  • Full GPT-4o integration with streaming responses
  • Mobile app with KG-powered recommendation
